20.26.6.1_rc2
-------------
- Fixed serial port handle state bugs: closed/failed handle states were inconsistent between open/read/write paths, occasionally bypassing reconnect logic
- Serial port auto-reconnect now retries the originally configured port/baud rate instead of being hardcoded to COM3
- Fixed SessionMonitor race that could deadlock service stop if stopSessionMonitor() ran before the monitor window finished creating
- Fixed Regedit::Write performing the registry create/open call up to 7 times per write, ignoring the requested value type, and leaking a handle on success
- Fixed Regedit::Read being unable to return the value it read (output parameter was passed by value)
- GA builds now log ERROR/WARNING/FATAL messages instead of suppressing all logging
- Wired up ServiceManager's service control handler (was a no-op stub) and MetricsCollector's cache invalidation/disable controls (previously no-ops)
- Fixed TrayApp tooltip truncation using byte size instead of character count, and hardened named pipe thread against a missing stop event
- build.sh now links SerialManager.cpp and 3kcheck.cpp, fixing undefined reference link errors
- Fixed serial worker thread exiting permanently if the serial port wasn't present at startup, instead of retrying as documented
- Brought LinuxPlatform serial handling in line with the above fixes (fd leak on termios setup failure, hardcoded baud rate, missing reconnect logic, syslog severity)
- Added authenticated named-pipe bridge (\\.\pipe\corestation_serial_bridge) letting a local admin-elevated app forward raw bytes to the serial port; ACL-restricted to BUILTIN\Administrators
- Added C2A command dispatch: BMC can now send `ping` (replies `pong`), `status` (replies with cpu/ram/uptime), and on Windows `shutdown` (initiates system shutdown); unrecognized commands still fall back to the message dialog
